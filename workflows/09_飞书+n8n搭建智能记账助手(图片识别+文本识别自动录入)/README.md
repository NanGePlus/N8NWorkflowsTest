# 飞书 + n8n 搭建智能记账助手（图片识别 + 文本识别自动录入）

## 功能介绍

通过飞书机器人实现智能记账：用户与记账助手机器人聊天，发送账单**图片**（微信支付截图、支付宝截图、发票拍照等）或直接输入账单**文本**（支付通知、银行短信、手动描述等），AI 自动识别内容，提取金额、商户、日期等信息，自动录入飞书多维表格；图片链路还会将原始账单图片作为**票根**一并保存至表格记录中。

## 技术架构

```
1. 用户通过飞书与“智能记账助手机器人”单聊，发送账单图片或账单文本消息
    ↓
2. 飞书服务器推送 `im.message.receive_v1` 事件至 n8n Webhook
    ↓
3. n8n Webhook 节点解析并获取消息内容
    ↓
4. 获取最新的 `tenant_access_token`
    ↓
5. 判断消息类型：
   ┌─────────────┬─────────────┐
   │   图片消息   │   文本消息   │
   └─────────────┴─────────────┘
        ↓                   ↓
【图片消息】            【文本消息】
下载图片二进制流          直接读取文本内容
        ↓                   ↓
6. 分别调用结构化识别助手，发送：
   - 图片通路传递 base64 编码图片及识别提示
   - 文本通路传递原始账单文本及识别提示
        ↓                   ↓
7. 获得模型返回的强制 JSON 格式化输出
        ↓
8. 校验输出：`code=200 && amount≠null` 是否识别成功？
   ┌─────────────┬──────────────┐
   │   是（成功）   │    否（失败）    │
   └─────────────┴──────────────┘
        ↓                    ↓
9. 【成功】写入飞书多维表格新记录（附带金额、商户、时间、分类等结构化内容）
        ↓
   - 【图片链路额外】：分片上传账单原图，保存至多维表格“票根”字段
        ↓
   - 回复用户录入成功，并主动推送明细内容

9. 【失败】回复用户识别失败原因

        ↓
流程结束
```

## 第一部分：飞书应用配置

### 步骤 1：创建企业自建应用

1. 访问 [飞书开放平台](https://open.feishu.cn/app)
2. 点击「创建企业自建应用」
3. 填写应用信息：
  - **应用名称**：智能记账助手
  - **应用描述**：发送账单图片或文本，AI 自动识别并录入记账
  - **图标**：可上传一个记账相关的图标
4. 点击「确定创建」

### 步骤 2：添加机器人能力

1. 进入应用详情页 → 点击「添加应用能力」
2. 选择「机器人」→ 点击「添加」
3. 配置机器人：
  - **如何开始使用描述**：发送账单图片或文本，AI 自动识别记账
4. 点击「保存」

### 步骤 3：开通权限

进入「权限管理」页面，开通以下权限（权限类型：应用身份）：

**必须开通（核心权限）：**

```
im:message.p2p_msg:readonly   # 读取用户发给机器人的单聊消息
im:message                    # 获取与发送单聊、群组消息
im:message:readonly           # 获取单聊、群组消息
bitable:app                   # 查看、评论、编辑和管理多维表格
base:record:create            # 新增记录
```

开通方式：

1. 在搜索框中搜索权限名称（如 `im:message.p2p_msg:readonly`）
2. 选中后点击「确认开通」
3. 确认开通，重复以上步骤直到全部开通

### 步骤 4：配置事件订阅

进入「事件与回调」→「事件配置」：

1. **启用加密策略**：选择「开启」（或「不开启」用于测试）
2. **订阅方式**：选择「将事件发送至开发者服务器」
3. **配置请求地址**：
  ```
  https://n8n.your-domain.com/webhook/feishu-smart-bookkeeping
  ```
  > 在点击保存时需要对请求地址进行有效性验证，请先导入并激活 **工作流配置文件/n8n配置飞书机器人事件订阅地址有效性测试.json**
4. **添加订阅事件**：
  - 搜索并添加 `im.message.receive_v1`（接收消息 v2.0）

### 步骤 5：发布应用

1. 进入「版本管理与发布」页面
2. 点击「创建版本」
3. 填写版本信息：
  - **版本号**：1.0.0
  - **更新说明**：初始版本
4. 点击「保存」
5. 点击「申请发布」→「确认申请」
6. 联系企业管理员审核通过

### 步骤 6：创建飞书多维表格

详情请参考 **多维表格配置说明.md** 文件内具体描述。

## 第二部分：n8n 工作流配置

### 工作流节点总览

导入 `飞书智能记账助手.json` 后，画布会按三段 Note 分区展示：**事件监听飞书机器人事件推送**、**处理图片消息**、**处理文本消息**。工作流实际执行链路如下：

```
接收飞书机器人消息推送（Webhook）
  → 解析飞书消息（Code）                     # 同时支持 text / image 两种消息类型
  → 设置应用凭证（Set）                      ← ⚠️ 需要填写飞书应用 + 多维表格参数
  → 获取飞书Token（HTTP Request）
  → 收到正确事件消息（Switch）               # code=200 且消息类型为 text 或 image
      ├─ [正常] 生成唯一字符串序列（Crypto） # 为飞书回复生成 uuid，避免重复发送
      │    → 机器人回复用户:处理中（HTTP Request）
      │    → 收到图片（IF）                  # 判断 has_image 字段
      │         ├─ [图片链路 True]
      │         │    → 获取文件二进制流（HTTP Request）
      │         │    → 账单图片结构化识别助手（AI Agent）← ⚠️ 需要配置 AI 凭证
      │         │         └─ 识别成功（IF）   # code=200 且 amount 非空
      │         │              ├─ [True] 固定字段（Set）
      │         │              │    → 新增记录到表格（HTTP Request）
      │         │              │    → 录入成功（IF）
      │         │              │         ├─ [True]  机器人回复用户消息:录入成功
      │         │              │         │    → 重新挂载图片（Code）
      │         │              │         │    → 获取图片文件大小（Code）
      │         │              │         │    → 分片上传素材-预上传（HTTP Request）
      │         │              │         │    → 重新挂载图片（Code）
      │         │              │         │    → 图片分片（Code）
      │         │              │         │    → Loop Over Items（循环分片上传）
      │         │              │         │         → 分片上传素材-上传分片（HTTP Request）
      │         │              │         │         → 等待3秒（Wait）
      │         │              │         │    → 合并数据统一处理（Aggregate）
      │         │              │         │    → 分片上传素材-完成上传（HTTP Request）
      │         │              │         │    → 更新记录 保存票根（HTTP Request）
      │         │              │         └─ [False] 机器人回复用户消息:录入失败
      │         │              └─ [False] 图片不符（IF）  # code=400
      │         │                   ├─ [True]  机器人回复用户:图片不符
      │         │                   └─ [False] 机器人回复用户:信息不足
      │         └─ [文本链路 False]
      │              → 账单文本结构化识别助手（AI Agent）← ⚠️ 需要配置 AI 凭证
      │                   └─ 识别成功（IF）    # code=200 且 amount 非空
      │                        ├─ [True] 固定字段（Set）
      │                        │    → 新增记录到表格（HTTP Request）
      │                        │    → 录入成功（IF）
      │                        │         ├─ [True]  机器人回复用户消息:录入成功
      │                        │         └─ [False] 机器人回复用户消息:录入失败
      │                        └─ [False] 文本不符（IF）  # code=400
      │                             ├─ [True]  机器人回复用户:文本不符
      │                             └─ [False] 机器人回复用户:信息不足
      └─ [异常] 机器人回复用户:事件异常
```

### 步骤 1：导入工作流

1. 进入 n8n 编辑器，点击左上角菜单 →「Import from File」
2. 选择 `工作流配置文件/飞书智能记账助手.json`
3. 点击「Import」，工作流会自动载入画布

---

### 步骤 2：配置飞书应用与多维表格参数

找到画布中的 **「设置应用凭证」** 节点（Set 类型），双击打开，将示例值替换为你自己的参数。飞书应用凭证和多维表格位置都集中配置在这个节点里：


| 字段名          | 说明               | 获取位置                                 |
| ------------ | ---------------- | ------------------------------------ |
| `app_id`     | 飞书应用的 App ID     | 飞书开放平台 → 应用详情 →「凭证与基础信息」             |
| `app_secret` | 飞书应用的 App Secret | 飞书开放平台 → 应用详情 →「凭证与基础信息」             |
| `app_token`  | 多维表格的 App Token  | 打开多维表格 → 浏览器地址栏 URL 中 `/base/` 后的字符串 |
| `table_id`   | 数据表的 Table ID    | 同一 URL 中 `?table=` 后的字符串             |


示例 URL 解析：

```
https://your-feishu.feishu.cn/base/QS6hbI5N5a5Og9sNHvpcJvdenWg?table=tblf5pOwZYvG97P2
                                    ↑ app_token                        ↑ table_id
```

> 该节点的 `app_id`、`app_secret` 会被「获取飞书Token」引用，用于换取 `tenant_access_token`；`app_token`、`table_id` 会被「新增记录到表格」和「更新记录 保存票根」引用。发布或分享工作流前，请确认 JSON 中没有保留真实 `app_secret`。

---

### 步骤 3：配置 AI 模型凭证

工作流包含**两套** AI Agent 节点：图片识别链路和文本识别链路各一套。每套 Agent 都挂载两个 OpenAI Chat Model，并连接一个 Structured Output Parser，用来把 AI 输出强制校验成可写入多维表格的 JSON。

#### 3.1 图片识别链路模型

**「账单图片结构化识别助手」** AI Agent 挂载：


| 节点名            | 模型           | 说明                      |
| -------------- | ------------ | ----------------------- |
| `gpt-5.4-mini` | gpt-5.4-mini | 主模型，负责视觉识别账单图片          |
| `gpt-5.4`      | gpt-5.4      | 备用模型，同时作为「强制格式化输出」的语言模型 |


配置方式：

1. 找到画布中的 **「gpt-5.4-mini」** 节点，双击打开
2. 在 Credential 下拉框中选择或新建一个 **OpenAI API** 凭证，填写 API Key
3. 同样找到 **「gpt-5.4」** 节点，配置相同或不同的 OpenAI API 凭证
4. 确认 **「强制格式化输出」** 节点已连接到「账单图片结构化识别助手」

#### 3.2 文本识别链路模型

**「账单文本结构化识别助手」** AI Agent 挂载：


| 节点名            | 模型           | 说明                       |
| -------------- | ------------ | ------------------------ |
| `gpt-5.4-mini` | gpt-5.4-mini | 主模型，负责结构化解析账单文本          |
| `gpt-5.4`      | gpt-5.4      | 备用模型，同时作为「强制格式化输出 」的语言模型 |


配置方式：

1. 找到画布下方文本链路中的 **「gpt-5.4-mini 」** 节点，双击打开
2. 在 Credential 下拉框中选择或新建一个 **OpenAI API** 凭证
3. 同样配置 **「gpt-5.4 」** 节点
4. 确认 **「强制格式化输出 」** 节点已连接到「账单文本结构化识别助手」

> 两个链路的模型节点均已设置 `responseFormat=json_object`、`timeout=300000`，适合结构化账单识别。

### 步骤 4：确认多维表格字段

工作流会通过「新增记录到表格」节点写入以下字段。请先按 **多维表格配置说明.md** 创建字段，字段名建议保持完全一致：


| 字段名       | 写入来源                                | 说明            |
| --------- | ----------------------------------- | ------------- |
| `录入者`     | 飞书发送者 `open_id`                     | 用于记录是谁发起记账    |
| `金额`      | AI 输出 `amount`                      | 支出为负数，收入为正数   |
| `货币代码`    | AI 输出 `currency`，为空时默认 `CNY`        | 如 CNY         |
| `商户名称`    | AI 输出 `merchant`，为空时默认 `未知商户`       | 收款方或商户        |
| `交易日期`    | AI 输出 `date` 转毫秒时间戳，缺失时使用当前时间       | 多维表格日期字段      |
| `交易时间`    | AI 输出 `time`，为空时默认 `暂无`             | HH:MM         |
| `交易类型`    | AI 输出 `transaction_type`，为空时默认 `其他` | 收入 / 支出       |
| `分类`      | AI 输出 `category`，为空时默认 `其他`         | 餐饮、交通等        |
| `支付方式`    | AI 输出 `payment_method`，为空时默认 `其他`   | 微信支付、支付宝、银行卡等 |
| `交易备注`    | AI 输出 `description`，为空时默认 `暂无`      | 商品说明或备注       |
| `原始OCR文本` | AI 输出 `raw_text`，为空时默认 `暂无`         | 便于人工复核        |
| `置信度`     | AI 输出 `confidence`，为空时默认 `低`        | 高 / 中 / 低     |
| `状态`      | 固定值 `待核实`                           | 用于后续人工确认      |
| `票根`      | 图片链路分片上传后的 `file_token`             | 仅图片消息会写入原始图片  |


> 图片链路先新增基础记账记录，随后通过飞书分片上传接口上传原图，再调用「更新记录 保存票根」把图片写回同一条记录的 `票根` 字段；文本链路只新增基础记账记录，不处理票根。

### 步骤 6：确认关键判断条件

导入后一般无需修改判断节点，但建议检查以下条件是否保持默认：


| 节点名             | 判断逻辑                                               | 作用                  |
| --------------- | -------------------------------------------------- | ------------------- |
| `收到正确事件消息`      | `code === 200` 且 `message_type` 为 `image` 或 `text` | 只处理支持的飞书消息          |
| `收到图片`          | `has_image` 为 true                                 | 图片消息进入图片链路，否则进入文本链路 |
| `识别成功` / `识别成功` | AI 输出 `code=200` 且 `amount` 非空                     | 只有识别到账单金额才写入表格      |
| `图片不符` / `文本不符` | AI 输出 `code=400`                                   | 区分非账单内容和信息不足        |
| `录入成功` / `录入成功` | 飞书接口返回 `code=0` 且 `msg=success`                    | 判断多维表格写入是否成功        |


工作流中的错误回复已内置：

- 非账单图片：回复「上传的图片不是有效的账单图片…」
- 非账单文本：回复「发送的文本不是有效的账单内容…」
- 未识别到有效金额：回复「账单信息获取异常…」
- 表格写入失败：回复「当前账单信息录入失败…」
- 不支持的消息类型：回复「当前仅支持与账单相关的文本或图片类型…」

### 步骤 7：激活工作流

1. 点击右上角「Active」开关，将工作流状态切换为激活
2. 在飞书中搜索「智能记账助手」机器人，发起单聊
3. 发送一张账单图片或直接输入账单文本，即可触发完整记账流程

## 第三部分：测试验证

### 测试步骤

**图片识别测试：**

1. 在飞书中与记账助手机器人聊天，发送一张微信支付或支付宝截图
2. 机器人应立即回复「已收到，正在为您智能识别账单内容，请稍候...」
3. 几秒后返回录入成功的明细消息
4. 打开多维表格，确认新记录已写入，且「票根」字段已附上原始账单图片

**文本识别测试：**

1. 直接发送账单文本，如：`瑞幸咖啡 -¥38.5 2026-04-24 09:32 微信支付 生椰拿铁`
2. 机器人应立即回复处理中提示
3. 返回录入成功明细，检查多维表格新记录

**验证数据准确性：**

- 金额是否正确（支出为负数）
- 商户名称是否正确
- 日期格式是否为 `YYYY-MM-DD`
- 分类和支付方式是否准确
- 图片链路是否成功保存「票根」附件
